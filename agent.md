# EasyFinanceCRM — Agent Mission Control

> every ai agent working on this project must read this file before writing a single line of code

---

## project vision

build a universal loan consultancy crm that manages the full lifecycle: lead acquisition, qualification, loan processing, disbursement, commission payouts, and support ticketing

the platform is pwa-first: one react codebase serves web, android, and ios. the web app is a progressive web app installable from the browser. native android apk and ios ipa are generated by wrapping the same codebase with capacitor 7.0 for play store and app store distribution

target users: loan consultancy companies, dsa networks, and financial service agencies across india

## rbac — five roles

all logic in the app must strictly enforce role-based access control for these five roles:

| role | code value | scope |
|------|-----------|-------|
| admin | `admin` | full system access, all data, all settings |
| manager | `manager` | team leads, see team leads, manage team staff |
| staff | `staff` | loan advisors, see only own leads and clients |
| franchise owner | `dsa` | external dsa partners, see franchise-scoped data |
| client | `client` | loan applicants, see only own application and tickets |

### enforcement points

- **backend**: every controller must use `Lead::scopeForUser($user)` or equivalent model scope. never return unscoped data
- **frontend**: route guards in `App.jsx` check role. sidebar/bottomnav items are role-filtered. never show ui elements the user cannot access
- **api**: every endpoint behind `auth:sanctum` middleware. role checks in controller or form request
- **database**: the `users.role` enum is `('admin','manager','staff','dsa','client')`

### role hierarchy

```
admin → sees everything
manager → sees own data + all team_members data (via team_leader_id)
staff → sees only assigned_to = self
dsa → sees only franchise_id = self.franchise_id
client → sees only records matching own phone/email
```

## coding standards

### general

- write clean, readable, self-documenting code
- single responsibility principle for all functions and components
- no dead code, no commented-out blocks left in production files
- keep files under 300 lines. split into smaller modules if needed

### laravel backend

- follow psr-12 coding style
- use form requests for validation (`StoreLeadRequest`, `UpdateLeadRequest`)
- use eloquent scopes for role-based data filtering
- use api resources for response formatting
- store business logic in service classes, not controllers
- migrations must always include a `down()` method
- use soft deletes for leads, clients, users
- all monetary values stored as `decimal(15,2)` in raw rupees
- commission rates stored as decimal fractions (0.0025 = 0.25%)

### react frontend

- functional components only, no class components
- use react hooks (`useState`, `useEffect`, `useMemo`, `useCallback`)
- use react context for global state (auth, leads, toast)
- use custom hooks for reusable logic (`useNetwork`, `useOfflineLeads`, `usePlatform`)
- prop types or jsdoc for component interfaces
- no inline styles except for dynamic values. use css classes from `crm.css`
- all interactive elements must have unique `id` attributes for testing

### comments and commits

- use less punctuation in code comments. no periods at the end of comment lines
- keep comments concise and lowercase
- explain why, not what

```js
// bad
// This function calculates the EMI based on the principal amount, rate, and tenure.
function calculateEMI() {}

// good
// emi formula using reducing balance method
function calculateEMI() {}
```

- commit messages must be all lowercase, no caps
- use conventional commit format

```
feat: add offline lead creation with indexeddb queue
fix: resolve duplicate phone detection on import
style: increase touch targets to 48px for store compliance
refactor: extract commission calculation into service class
```

## mobile-first rules

### responsive design

- every ui component must be 100% responsive across all breakpoints
- breakpoints: 480px (phone), 768px (tablet), 1024px (desktop)
- design mobile-first: start with smallest screen, enhance for larger
- all touch targets must be minimum 48x48px (play store and app store requirement)
- form inputs must be minimum 44px height with 16px font size (prevents ios auto-zoom)

### no footer rule

- web: no footer element anywhere in the app. the sidebar handles all navigation
- this rule is absolute and applies to every page

### mobile bottom navigation bar

- visible only on native platforms and viewports <= 768px
- replaces the sidebar on mobile
- four tabs: dashboard, leads, pipeline, more (hamburger for remaining items)
- fixed at bottom with `env(safe-area-inset-bottom)` padding for ios
- when bottom nav is visible, sidebar must be hidden
- main content must have `padding-bottom: 72px` to avoid overlap

### safe areas

- respect ios notch and home indicator via `env(safe-area-inset-*)`
- topbar must include `padding-top: calc(8px + env(safe-area-inset-top))`
- android navigation bar must not overlap content

## native-ready logic (capacitor 7.0)

### platform detection

always use the platform utility before accessing native features:

```js
import { Capacitor } from '@capacitor/core'
const isNative = Capacitor.isNativePlatform()
const isAndroid = Capacitor.getPlatform() === 'android'
const isIOS = Capacitor.getPlatform() === 'ios'
const isWeb = Capacitor.getPlatform() === 'web'
```

every native feature must have a web fallback. never assume capacitor plugins are available

### push notifications

- native: use `@capacitor/push-notifications` plugin for fcm (android) and apns (ios)
- web: use web push api with service worker and vapid keys
- backend: laravel notifications with database + fcm + webpush channels
- device tokens stored in `push_devices` table (user_id, platform, token)
- triggers: follow-up reminders, lead assignments, announcements, ticket replies, commission approvals

### camera and gallery (document uploads)

- native: use `@capacitor/camera` plugin with three options
  - `CameraSource.Camera` — take photo
  - `CameraSource.Photos` — pick from gallery
  - file input fallback — pick any file
- web: standard `<input type="file">` with accept attribute
- the `CameraUpload.jsx` component handles both paths transparently
- all uploads go through `POST /api/{resource}/documents` as `multipart/form-data`
- supported types: pdf, jpg, png, doc, docx
- max sizes: 10mb for documents, 50mb for lms materials

### biometric authentication

- native only: use `@capacitor-community/biometric-auth` plugin
- flow: first login with password → prompt to enable biometric → store token securely → subsequent opens use fingerprint/faceid
- token stored in `@capacitor/preferences` (encrypted shared preferences on android, keychain on ios)
- if biometric fails, fall back to password login screen
- web: no biometric, token in localstorage

### offline support

- leads: full offline crud via indexeddb (dexie.js). mutations queued and synced on reconnect
- lms/knowledge base: stale-while-revalidate caching. content readable offline after first visit
- calculator: fully offline (client-side math, no api calls)
- dashboard: show last-cached stats with "offline" indicator
- use `@capacitor/network` plugin on native, `navigator.onLine` on web

## workflow instructions

### before starting work

1. read this `agent.md` file completely
2. read `docs/PRD.md` for what to build
3. read `docs/TDD.md` for how to build it
4. check the existing codebase structure before creating new files
5. check if a similar component or utility already exists before building from scratch

### during development

1. make small, focused changes. one feature per commit
2. test responsiveness at 480px, 768px, and 1024px viewpoints
3. verify offline behavior by simulating network disconnect
4. verify role-based access by testing as each of the five roles
5. use the integrated browser tool to verify ui changes visually
6. run `npm run build` periodically to catch build errors early

12. **no new dependencies without approval** — keep the bundle small
13. **test all five roles** — admin, manager, staff, franchise, client
