# Phase 3 Implementation Plan: Support & Training Strategy

## 1. Technical Breakdown by Module

### 1.1 Staff Module (Advanced)
Focus: Self-service tools and commission transparency.
- **React Components**:
  - `VirtualIDCard`: Renders a download-ready and shareable digital card.
  - `CommissionDashboard`: Tabular view of self-commissions and payout statuses.
  - `FollowUpReminders`: Dedicated mobile-optimized list for today's tasks.
- **Laravel API Endpoints**:
  - `GET /api/staff/me`: Fetches extended profile with ID card metadata.
  - `GET /api/payouts/history`: Paginated list of staff commissions.
- **Database Interactions**:
  - Query `users` for ID card metadata.
  - Query `commissions` and `payouts` scoped to `user_id`.

### 1.2 Franchise Module
Focus: Business parity with Internal Managers.
- **React Components**:
  - `FranchiseStatsView`: Visual charts for franchise-only performance.
  - `SupportTicketPortal`: Interface to raise and track franchise-admin tickets.
- **Laravel API Endpoints**:
  - `GET /api/franchise/analytics`: Aggregated lead data for the franchise scope.
  - `POST /api/tickets`: Specialized endpoint for franchise issue reporting.
- **Database Interactions**:
  - Scope `Lead::where('franchise_id', ...)` for all analytics queries.

### 1.3 Client Module (Portal)
Focus: Transparency and document management.
- **React Components**:
  - `LoanTimeline`: Visual tracker for SANCTIONED -> DISBURSED journey.
  - `ClientDocumentVault`: Simplified camera-ready upload interface.
- **Laravel API Endpoints**:
  - `GET /api/client/profile`: Role-scoped login to see only their lead record.
  - `POST /api/client/documents`: Direct upload to their own lead file.
- **Database Interactions**:
  - Scope queries to `Lead::where('phone', $user->phone)`.

## 2. Coding Patterns & Logic

### 2.1 Virtual Visiting Card (Digital ID)
- **Pattern**: **Canvas-to-Share**
- **Implementation**:
  - Use HTML5 `<canvas>` via `useRef` to draw the 1012x638px (Standard ID) card background and overlay text/logo.
  - **Native**: Use `canvas.toDataURL()` -> `Filesystem.writeFile` -> `Share.share`.
  - **Web**: Use `canvas.toBlob()` -> `URL.createObjectURL` -> download anchor.

### 2.2 Loan Calculator Logic
- **Pattern**: **Pure Utility / Offline Math**
- **Logic**:
  - `utils/loanCalc.js`: Functional exports for `calculateEMI`, `calculateEligibility`, and `getFOIR`.
  - No API calls to ensure it works in dead zones (trains, remote field sites).
  - Formula: `EMI = [P x R x (1+R)^N] / [(1+R)^N-1]`.

### 2.3 Support Ticket Threading
- **Pattern**: **Parent-Child Recursive Threading**
- **Implementation**:
  - `Ticket` model with `is_reply` (boolean) and `parent_id`.
  - Frontend: `TicketTimeline.jsx` maps through specific `replies` relation sorted by `created_at`.
  - Status logic: `AdminReply` automatically triggers `status = 'In Progress'` unless specifically set to `Closed`.

## 3. PWA & Native Integration (Capacitor 7.0)

### 3.1 Lock-Screen Reminders
- **Plugin**: `@capacitor/push-notifications`
- **Strategy**:
  - At `follow_up_time`, Laravel triggers a background job to dispatch an FCM/APNs notification.
  - The notification payload includes `lead_id` for deep-linking.
  - Frontend `PushRegistrationService` handles the native permission request on first Staff/Manager login.

### 3.2 CIBIL Score Links
- **Plugin**: `@capacitor/browser`
- **Implementation**:
  - Admin stores URLs in `bank_policies` (CIBIL Category).
  - Staff clicks a URL -> `Browser.open({ url: ... })`.
  - Ensures a seamless return to CRM after the check is complete.

## 4. Data Flow & Caching

### 4.1 Role-Based Dashboard Strategy
- **Fetching**:
  - Endpoint: `GET /api/dashboard/{role}`.
  - Context: `DashboardContext` handles the loading state and role-specific data shape.
- **Caching (Service Worker)**:
  - **Strategy**: `NetworkFirst` via Workbox.
  - **Fallback**: If the API fails or is offline, the SW pulls the last successful JSON from the browser's `dashboard-cache`.
  - **Dexie.js Integration**: For high-volume lead data within the dashboard, Dexie provides SQL-like querying on the cached set to allow offline "Filter-by-Stage" functionality.
